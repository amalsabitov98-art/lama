# Turon Tour — Mobile App

All-in-one mobile app for **Turon Tour**, a tour operator based in Tashkent.
The app serves three roles from one codebase — **tourist**, **agent**, and
**operator**.

> **This repository is Phase 1: the app skeleton.** It sets up the foundation
> (architecture, theming, localization, roles, and a mock login) that the
> booking features will be built on in later phases. There are no booking
> screens yet — that is by design.

---

## What Phase 1 delivers

- ✅ Flutter + Material 3 project with a **Clean Architecture, feature-first**
  layout (`data` / `domain` / `presentation`).
- ✅ **Custom travel brand theme** — warm, Uzbekistan-inspired palette
  (terracotta / sand / turquoise), fully worked-out **light and dark** themes,
  with all colors, spacing, radii and elevation kept as **design tokens** in
  one place.
- ✅ **Localization** in **Uzbek (uz) / Russian (ru) / English (en)** via
  `flutter_localizations` + `intl` and `.arb` files. Every user-facing string is
  localized — no hard-coded text. Language switches **live**, no restart.
- ✅ **Drift (SQLite)** database with `Users` and `Agents` tables, plus a
  **mock seeder** that inserts 3 accounts on first launch.
- ✅ **Mock login / RBAC** — pick a role with one tap (no passwords yet). The
  session is persisted in `shared_preferences`.
- ✅ **`go_router` with a role-aware redirect guard** — signed-out users are
  sent to login; signed-in users land on (and are locked to) their own role's
  home.
- ✅ Per-role **home placeholders** with a bottom navigation bar (Home +
  Profile).
- ✅ **Shared profile** — switch language, switch theme (light / dark / system),
  and log out.

## Getting started

> Flutter is **not** committed with this repo, and the native platform folders
> (`android/`, `ios/`) plus Drift/localization **generated code** are produced
> by tooling. Run the steps below once after cloning.

### 1. Prerequisites

- Flutter SDK (latest stable) — <https://docs.flutter.dev/get-started/install>
- Xcode (for iOS) and/or Android Studio + SDK (for Android)

### 2. Generate the native platform folders

The `lib/` source, `pubspec.yaml`, and configs are all here; the platform
scaffolding is generated by Flutter:

```bash
flutter create --platforms=android,ios --org uz.turontour .
```

This adds `android/` and `ios/` without touching `lib/`.

### 3. Install dependencies

```bash
flutter pub get
```

### 4. Generate code (Drift + localizations)

Drift tables/DAOs and the localization classes are code-generated:

```bash
# Drift: creates the *.g.dart files
dart run build_runner build --delete-conflicting-outputs

# Localizations: creates lib/core/localization/generated/app_localizations.dart
flutter gen-l10n
```

> `flutter gen-l10n` also runs automatically during `flutter run`/`build`
> because `generate: true` is set in `pubspec.yaml`; it is listed here so you
> can generate on demand.

### 5. Run

```bash
flutter run          # pick an iOS simulator or Android emulator/device
```

The app compiles and runs on **iOS and Android**.

## Project structure

```
lib/
├── app.dart                       # Root MaterialApp.router (theme + locale + router)
├── main.dart                      # Bootstrap: prefs, DB, seeding, ProviderScope
│
├── core/
│   ├── theme/                     # Design tokens + light/dark themes
│   │   ├── app_colors.dart        #   brand palette + ColorSchemes
│   │   ├── app_spacing.dart       #   spacing / radius / elevation tokens
│   │   ├── app_typography.dart    #   text theme
│   │   └── app_theme.dart         #   assembles ThemeData from tokens
│   ├── router/                    # go_router + role redirect guard
│   │   ├── route_paths.dart
│   │   └── app_router.dart
│   ├── localization/
│   │   ├── arb/                    #   app_uz.arb / app_ru.arb / app_en.arb
│   │   ├── generated/              #   AppLocalizations (generated, git-ignored)
│   │   └── role_l10n.dart          #   role → localized label helper
│   ├── providers/                 # Riverpod infrastructure providers (DI)
│   └── widgets/                   # Reusable widgets (RoleCard, SectionPlaceholder)
│
├── domain/                        # Pure Dart: no Flutter/DB imports
│   ├── entities/                  #   User, AgentProfile, UserRole
│   ├── repositories/              #   AuthRepository (abstract)
│   └── usecases/                  #   SignInWithRole, SignOut, GetCurrentUser
│
├── data/
│   ├── db/                        # Drift schema + DAOs
│   │   ├── tables.dart
│   │   ├── app_database.dart
│   │   └── daos/
│   ├── mock/                      # Mock accounts + seeder
│   ├── local/                     # SessionStore + PreferencesStore (shared_preferences)
│   └── repositories/              # AuthRepositoryImpl (Drift-backed)
│
└── features/
    ├── auth/                      # Login / role picker + AuthController
    ├── tourist/                   # Tourist home (placeholder)
    ├── agent/                     # Agent home (placeholder)
    ├── operator/                  # Operator home (placeholder)
    └── shared/                    # Profile, splash, language/theme pickers,
                                   # RoleHomeScaffold, locale/theme controllers
```

**Layering rule:** `presentation → domain ← data`. The domain layer depends on
nothing else; presentation and data both depend on domain abstractions. Riverpod
providers in `core/providers` wire the concrete implementations together.

## Phase 2 — Tourist role (in progress)

Phase 2 fills in the **Tourist** experience, built sub-step by sub-step. All
data is mock data stored in Drift — there is no backend.

**Sub-step 2.1 — Data layer (done):**
- New Drift tables: `Tours`, `SeriesDepartures`, `Bookings`,
  `PaymentInstallments`, `Vouchers`, `Reviews`, `Wishlists`.
- Localized tour content (uz/ru/en) via `LocalizedText` / `LocalizedList`
  type converters (`lib/data/db/converters.dart`).
- Mock catalogue of **12 real Uzbek destinations** (Samarkand, Bukhara, Khiva,
  Nurata & Aydarkul, Chimgan, Tashkent, Aral Sea, Fergana, Shakhrisabz,
  Sentyab, Charvak, Termez) with 2–4 departures and reviews each, realistic
  UZS prices, and mock AI review summaries — see `lib/data/mock/mock_tours.dart`.
- For the mock tourist **Aziza Karimova**: 3 pre-made bookings (confirmed /
  pending-with-overdue / completed) with payment plans and vouchers, plus 2
  wishlisted tours.

> **Schema upgrade note:** the database `schemaVersion` is now `2`. Because this
> is a mock/demo app, the migration is destructive — on upgrade it drops and
> recreates all tables, and the seeder repopulates on next launch. After
> pulling, always re-run code generation:
> ```bash
> dart run build_runner build --delete-conflicting-outputs
> ```

**Sub-step 2.2 — Storefront + tour details (done):**
- Tourist shell with 4 tabs: **Home / Search / My Trips / Profile** (Search &
  My Trips are placeholders until 2.3 / 2.5).
- **Home storefront**: greeting, "Popular tours" and "Upcoming departures"
  carousels, category chips (All / Cultural / Nature / Adventure / City) that
  filter the catalogue.
- **Tour details**: photo gallery, highlights, description, included / not
  included, meeting point (photo + address + coordinates), reviews with an "AI
  summary" block, and a departures list with per-date price, seats-left and
  status chips.
- **Wishlist**: tap the heart on any card or the details screen; saved tours
  live under the Home ❤ action.
- New reusable widgets in `core/widgets`: `TourCard`, `RatingStars`,
  `PriceTag`, `SectionHeader`, `StatusChip`, `TourImage`.

> The "Book now" button is a placeholder until sub-step 2.4.

Upcoming sub-steps: 2.3 search & filters · 2.4 booking + mock payment ·
2.5 voucher (QR/PDF) + My Trips · 2.6 polish.

## Notes

  colors/paddings.
- Generated files (`*.g.dart`, `core/localization/generated/`) are git-ignored
  and recreated by the codegen steps above.
